# wasmvm v3 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `modules/light-clients/08-wasm` from `github.com/CosmWasm/wasmvm/v2 v2.3.2` to `github.com/CosmWasm/wasmvm/v3 v3.0.4` with zero behavioral or API change to 08-wasm itself.

**Architecture:** Pure dependency bump. wasmvm v3.0.4 keeps every method signature, type, and interface that 08-wasm consumes. The migration is an atomic import-path replace across 21 Go files plus a single string-literal update in the simapp build-info check. The existing 08-wasm test suite is the regression harness — there is no new behavior to test.

**Tech Stack:** Go 1.25, `github.com/CosmWasm/wasmvm/v3`, `cosmos-sdk`, `ibc-go/v11`. Module isolated to `modules/light-clients/08-wasm/` (its own `go.mod`); root ibc-go and `simapp/`/`e2e/` modules do not depend on wasmvm.

**Spec:** `docs/superpowers/specs/2026-04-29-wasmvm-v3-upgrade-design.md`

## Task 1: Bump go.mod and replace all imports atomically

**Why this is one task, not many:** The imports and `go.mod` must change together; in between the two states the module would not compile. We make all 21 import edits, the `go.mod` edit, and the `root.go:408` string-literal edit in a single commit, then run `go mod tidy` and `go build` to prove the atomic edit is internally consistent.

**Files:**

- Modify: `modules/light-clients/08-wasm/go.mod` (line 16)
- Modify: all 21 `.go` files listed in the inventory above
- Modify: `modules/light-clients/08-wasm/go.sum` (regenerated)

- [ ] **Step 1.1: Edit `go.mod` line 16**

Change:
```
github.com/CosmWasm/wasmvm/v2 v2.3.2
```
to:
```
github.com/CosmWasm/wasmvm/v3 v3.0.4
```

- [ ] **Step 1.2: Replace `wasmvm/v2` with `wasmvm/v3` in every Go file**

Apply the substitution `github.com/CosmWasm/wasmvm/v2` → `github.com/CosmWasm/wasmvm/v3` to all 21 files in the inventory above. This includes:

- Import lines like `wasmvm "github.com/CosmWasm/wasmvm/v2"` → `wasmvm "github.com/CosmWasm/wasmvm/v3"`
- Import lines like `wasmvmtypes "github.com/CosmWasm/wasmvm/v2/types"` → `wasmvmtypes "github.com/CosmWasm/wasmvm/v3/types"`
- The string literal on `testing/simapp/simd/cmd/root.go:408`:
  ```go
  if d.Path != "github.com/CosmWasm/wasmvm/v2" {
  ```
  becomes
  ```go
  if d.Path != "github.com/CosmWasm/wasmvm/v3" {
  ```

The local Go alias names (`wasmvm`, `wasmvmtypes`) stay the same — only the module path inside the import string changes.

You can do this with a single `find`/`sed` invocation from inside `modules/light-clients/08-wasm/`. Use `-type f -name '*.go'` so the substitution is scoped to Go source:

```bash
cd modules/light-clients/08-wasm
find . -type f -name '*.go' -print0 | \
  xargs -0 sed -i '' 's|github.com/CosmWasm/wasmvm/v2|github.com/CosmWasm/wasmvm/v3|g'
```

(Note: `sed -i ''` is the BSD/macOS form; on Linux drop the empty-string arg: `sed -i '...'`. Verify which one you're on with `uname -s` — Darwin is BSD.)

## Task 2: Verify the existing test suite still passes

The 08-wasm test suite is the regression harness. Behavior should be identical, so any failure indicates either a v3 source-incompatible change we missed in the spec or a pre-existing flake.

**Files:** none — this task only runs commands.

- [ ] **Step 2.1: Run the full test suite under default tags**

```bash
cd modules/light-clients/08-wasm
go test ./...
```

Expected: all packages report `ok` or `[no test files]`. No `FAIL` lines.

If a test fails:
1. Re-run the failing test in isolation with `-v -count=1` to rule out cache effects.
2. Compare its behavior against the same test on a v2 baseline (e.g., `git stash && go test ./failing/package -run TestName -v && git stash pop`). If v2 also fails, it's a pre-existing flake — report and move on.
3. If only v3 fails, do not patch the test or production code blindly. Read the failure carefully and check whether it touches one of the v3 type changes we already know about (`Env.TransactionInfo`, `IBCQuery.FeeEnabledChannel`, `WasmQuery.RawRange`). Report the failure with the diagnosis before fixing.

```bash
cd modules/light-clients/08-wasm

```

Expected: passes (some packages will skip tests that require the real VM; that is fine and matches v2 behavior).

- [ ] **Step 2.3: Sanity-check the libwasm version function**

This is a smoke test for the string-literal fix on `root.go:408`. We're not running simd, just confirming the function doesn't return `""`.

Run:

Then run:
```bash
cd modules/light-clients/08-wasm

package main

import (
	"fmt"
	"runtime/debug"
)

func main() {
	bi, _ := debug.ReadBuildInfo()
	for _, d := range bi.Deps {
		if d.Path == "github.com/CosmWasm/wasmvm/v3" {
			fmt.Println("found:", d.Path, d.Version)
			return
		}

	fmt.Println("MISSING")

EOF
go run /tmp/check_libwasm.go
rm /tmp/check_libwasm.go
```

Expected: `found: github.com/CosmWasm/wasmvm/v3 v3.0.4`. If output is `MISSING`, the build-info dependency lookup is broken and the substitution missed something — go back and re-grep for `wasmvm/v2`.

(You can skip this check if Step 1.3 already confirmed zero `wasmvm/v2` matches — the function is purely a string lookup.)
