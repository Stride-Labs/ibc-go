# 08-wasm: Upgrade wasmvm v2 → v3

**Date:** 2026-04-29
**Module:** `modules/light-clients/08-wasm`
**Module path:** unchanged (`github.com/cosmos/ibc-go/modules/light-clients/08-wasm/v11`)

## Goal

Upgrade the 08-wasm light-client module to depend on `github.com/CosmWasm/wasmvm/v3 v3.0.4` (latest stable v3 at time of writing) with **zero behavioral or API change** to the 08-wasm module itself. This is a pure dependency bump.

## Non-goals

- No bump of the 08-wasm Go module path to `/v12`. Public API of 08-wasm does not change.
- No exposure of new wasmvm v3 features (IBC2 entrypoints, `WasmQuery.RawRange`, populated `Env.TransactionInfo.Hash`).
- No refactor of the gas register, mock engine, or store adapter beyond the import path.
- No changes to the root ibc-go module, `simapp/`, or `e2e/` (none of them depend on wasmvm).

## Context: wasmvm v2.3.x → v3.0.4 caller-side changes

| Surface | v2.3.x → v3 |
| --- | --- |
| Module path | `wasmvm/v2` → `wasmvm/v3` (the only mandatory change for callers) |
| `*VM` method signatures (`Instantiate`, `Sudo`, `Query`, `Migrate`, `StoreCode`, `StoreCodeUnchecked`, `Pin`, `Unpin`, `GetCode`, `RemoveCode`, `GetMetrics`, `NewVM`) | Identical |
| `types.Checksum`, `KVStore`, `GoAPI`, `GasMeter`, `Iterator`, `Querier`, `UFraction`, `Reply`, `Event`, `EventAttribute`, `Array`, `GasReport` | Identical |
| `types.Env.TransactionInfo` | Adds optional `Hash []byte` (`omitempty`); zero-valued by default — no action |
| `types.IBCQuery.FeeEnabledChannel` | Removed in v3. **Confirmed not referenced anywhere in 08-wasm.** |
| `types.CosmosMsg.IBC2`, `IBCMsg.IBC2`, `WasmQuery.RawRange`, `IBCSourceCallbackMsg.Transfer` | New optional fields; not consumed by 08-wasm |
| New `*VM` methods: `IBC2PacketReceive/Ack/Timeout/Send` | Additive; not exposed via the 08-wasm `WasmEngine` interface |

Every method 08-wasm calls into wasmvm has an unchanged signature, so the migration reduces to a mechanical import replace.

## Risks

- **Underlying Rust gas costs may shift between wasmvm major versions.** The Go wrapper API for gas accounting (`UFraction`, `GasReport`) is unchanged, but the actual cost numbers reported by the Rust runtime can drift. This is expected behavior of a wasmvm major upgrade and is not addressed by this change. Worth a one-line note in the 08-wasm CHANGELOG so chain integrators are aware.
- **`Env.TransactionInfo.Hash` defaults to `nil`.** 08-wasm constructs `Env` values from the Cosmos SDK context and does not populate the new optional `Hash` field. Light-client sudo/query contracts should not depend on it; leaving it `nil` is the minimal choice consistent with current behavior.
